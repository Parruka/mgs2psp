4. THE RULE'S SAFETY, AS FAR AS THE CONTAINER CAN SHOW IT
On the PSP an ME walk reads the game's memory after the game has moved on. Read in code [C] (psp/xl_psp.c mq_frame, gl25's
rule lchk4): a hook with records waits for the walk before it, and so does the second hook after the walk's own, so what a

idle there, +0.2 ms in the model); gl33's in-place ME turns against gl31's native ME turns = retrain + rule. gl33's plain
turns fall on gl31's builder turns. See section 9 for the swapped order.

 - The runtime's training set no longer fits the emulator's memory as one instrumented build: trained in two halves, rtb
   (boot_rt.o + gen_dispatch.o) and pic (the picture objects + xl_psp.o), each with a smaller texture pool (TEXKB 1024 /
   1664 instead of the cfg's): 571,084 texture-pool refusals in rtb (they do not touch boot_rt's code [I]); in pic 13,311 of
   18,196 conversions refused and 35,247 evictions over 5.72 M uses, so the texture cache's code was trained under more
   pressure than a real run has. Hashes equal in both.
 - The stage runs used MGS2_ME_PIC=0, TEXKB 256 and MGS2_ME_PIC_GE2=0, the game run MGS2_ME_PIC=0 and TEXKB 1024 (memory);
   the state is equal (hash lines). The inside trace started from a cfg with 'deck 31800' for the same reason.
 - gen.o is compiled with -fno-partial-inlining in every build but the counting one: with the new profile GCC split
   P1214a0 (the builder, which sits behind the native wrapper) and inlined its head into two callers, which would pass the
   wrapper by; psp.sh now stops a build whose gen.o holds a clone of it or other references than 2 calls and 1 table word.
   G3 is the proof that no caller took it in (emulator hashes = twin's with native in every turn).
 - The trace and order windows and the equal weights of the deck and inside routes are gl20's, although the PSP run ends
