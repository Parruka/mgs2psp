3. The reuse's new rule: re-use only when it pays [C]
What it does (ge/xlate.c, xl_nr_begin and xl_nr_pic; key MGS2_NAT_RRULE, 1 by default, 0 = gl36's rule):
- Replays are unchanged. The rule only decides whether a run that did not replay is recorded.
- A run is recorded only while each of the last two pictures had at least half of its tried groups in runs that either replayed or
  were the same as in the picture before.
- Otherwise the run is fed plain. Its "shadow" is written at its head entry: length, VU buffers, and two 32-bit hashes of its records'
  words. The entry's head becomes 0xffff, so no replay can use it.
- A later run that equals its shadow counts as a good run. This is how the rule notices that the camera has settled again.
- On the reuse's on-turns only (MGS2_NAT_REUSE_CYCLE=1,1,0,0, as gl36); off-turns are plain, as before.
- New lines: 'nat reuse rule vb A-B' per turn and 'reuse rule totals (gl37)' on the PSP; 'natreuse: ... rule' on the twin.
How it was chosen:
- From the twin's runs (dump MGS2_NAT_RDUMP, x86 only), simulated by build_gl37/nrsim.py.
- The simulator reproduces gl36's twin modes run for run (0 differing) and its totals exactly.
- Rules tried: per run (stab), per picture with thresholds (pic, pic2, pich, stabpic, picstab). Outputs: sim_rules1.txt,
  sim_rules2.txt, sim_pic2_2304.txt.
- pic2:0.5 kept the wait's gain and lost least in the walk. The twin implementation matches the simulator exactly.

5. Units note (affects every "PSP/model 0.5" figure)
Facts [C]:
- steps.csv has one row a vblank. full and lite alternate, so there is one picture every two rows (emu_n2/steps.csv).
- The model scripts (mtot35.py, pairmean36.py) divide a window by 40 pictures (80 vblanks).
- gl36's report reads "ms a picture over 40 pictures = 80 vblanks = ms a step".
- natsplit_summary's "native ms/step d" column is us a group x groups / 100 vblanks.
- The PSP's "ms a step" is a vblank: split36pc.py reads the 'window vb B: N steps, mean X ms' lines, and a window of 100 vblanks has
  100 steps (emu_n2/log.txt 'window vb 200: 100 steps'); its ME figures are turn ms / 100.
So the model's "ms a step" is a picture, which is two PSP steps [C].
Inference [I]: the observed PSP/model ~0.5 is mostly this factor, not a model overrate:
- cull 0.55 and reuse 0.5;
- per group the reuse agrees: PSP -5.4 us, model -4.7 us.
Basis: the units above, and both levers giving the same ratio. The model's own error is then small for these ME-side levers.
UNSURE only in how much of the 0.5 is units and how much is model error; the units part is [C].
