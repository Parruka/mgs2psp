HEAP: WHAT WAS DECIDED AND WHY
- (a)-(c) as asked. On the no-PGO package build n41d the gate read 103 KB [C emu]. The PGO image is 72 KB larger (text +68 KB), and
  newlib's heap top is fixed (PSP_HEAP_SIZE_KB(-1024): all free memory but 1 MB), so every byte of image comes off the room: with
  gl40's pads (ME_PRE 0x1d00, END_PAD 0x1a00) about 12 KB, without ME_PRE/END_PAD about 26 KB [I: ELF sizes]. The gate would fail.
- Decision: MAIN_KB 256 -> 128 (the main thread's own stack part, guest thread 1; it uses 2.9 KB in every run since gl16: 2,948 of
  129,472 B in this package's run [C emu]). The main thread's stack shrinks by 128 KB, so newlib's heap top moves up 128 KB
  (0be7bfff -> 0be9bfff [C emu]) and the worst moment reads 135 KB. ME_PRE and END_PAD KEPT (they place the h39 block and the heap
  block on gl40's data-cache sets; with them the gate passes four-fold); ME_PRE retuned to 0x340 for the new image, END_PAD 0x1a00
  (heap block 0b247900 = gl40's offset 0x1900 in its page). Not movable by any pad: g_mem +0x680 (boot_rt's .bss grew by P1/P3's
  tables before it) and some .bss groups.
- The PSP has had more room than the emulator (gl40 PSP end of run: 2,608 KB in one block; the emulator: 64 KB) [C gl40 PSP read];
  the first 'memory (gl41)' line on the PSP gives its heap end.
