# gl34 plan: gl33 + in place everywhere + the native path's ME split on the PSP + a cheaper native front end and tracking (in turns) + a fresh PGO, 2026-11-21 11:40 UTC

Lead plan for the MGS2 port thread. gl33's PSP run (psp_harness.md "Build gl33", read 11:20) was exact and 6-8% faster, nearly all from the retrain. Two facts set gl34:
- In the rain the ME is the limit [C gl33]: ME turn ~92.8 ms a step = walks ~65.9 (of which native ship time ~21.9) + frame ends and lists ~22.3 + idle ~1; the main CPU waits for fills ~13.5 a step.
- The native ship path costs the ME nearly what the builder path did (gl31: walk -2.8 a step only). The model's split (build_gl32 report, model_split): of the ship's 74.6 ms of ME work a picture the per-vertex converter is 4.7; the hand-off copy 14.4, front end 13.6, call + GS tracking 15.7, converter per group 11.3, depth range 2.1, cut 2.7, xc_call 3.0, its list build 3.9. The model overrated the in-place rule 4x on the PSP (-5.8 a step modelled, ~-1.5 [I] measured), so the model's split is not trusted alone.
So before more kinds go native (design steps 2-3, which reuse the same machinery), the native machinery itself must get cheap, and the PSP must say where its time goes.

## What gl34 is
1. Tree /home/claude/t34 = t33. MGS2_NAT_INPL on in every turn (cfg), MGS2_NAT_CYCLE=3,3,3,3 as gl33.
2. **ME split counters on the PSP (exact, logs only):** inside the native time and the walk, per 100-vb turn, the ME's time in: the hand-off copy, the native front end, call + GS state tracking, the converters (per group and per vertex), depth range / cut, the native groups' list build, and the walk's non-native part by chain (the frame's chains 0-10, design §1.6) with call counts. One 'nat split' line and one 'me chains' line per turn. Timer cost per read measured and stated; keep the counters cheap enough that a turn with them on is within ~1% of off (put them behind a switch, on in the delivered cfg; prove the cost on the emulator and in the model).
3. **The lever, in turns:** a cheaper front end and GS tracking for native ship groups (read the native path in t33 first: ge/xme*, xconv.c, the nat record merge, xc_call / xm_call / tk_* tracking). The aim: native groups carry state the converters need precomputed per mesh / per group (not re-derived per call through the PS2 GS tracking), skip tracking work whose results native batches never use, and batch calls. Target [C model]: native ship ME work a picture -30% or more in the rain wait's ME turn, and no loss elsewhere. Behind its own key in turns (e.g. MGS2_NAT_FAST_CYCLE=1,1,0,0, so plain turns = gl33's in-place turns). HARD GATE: the batches are identical to today's (the same GE words) in every picture: lane identity as step 0/1 proved. If some part cannot stay identical, leave it out of gl34 and say what it would need.
4. A FRESH PGO + code order on t34 with both arms trained (gl33's method: build_gl33 pgo_*/order33.sh/layout_sim; gen.o -fno-partial-inlining; psp.sh's stop on a split native wrapper; the lost-profile check).
5. Everything else as gl33's cfg (FLIPWAIT_FROM=0, DZ X whole run, ME_PIC 4, live captures, short run to 31,400).
