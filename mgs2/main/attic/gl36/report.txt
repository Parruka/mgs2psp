Findings:
1. Not keep 1 or the per-picture reset [C model].
   - The work is the same: instructions differ by -0.1 % .. +0.3 %.
   - No keep or reset code shows. The reset is one store per picture in gl_begin. The keep acts only on fast native groups,
     and these windows have none.
   - The instruction changes that exist are spread over the game's own P* functions and the GS path, as a slightly different
     run of the same scene would give.
2. The I-miss part is the code order, i.e. the retrain [C model + I].
   - It is +2.9 .. +3.5 k I-misses a picture in all four windows, in both turns. That is +0.59..+0.70 ms, beyond the same-ELF
     spread (at most +1.8 k).
   - The fully associative count (capacity only) is LOWER than gl35's in all four windows (-1.2 .. -1.8 k). The code these
     windows run is no bigger. The extra misses are conflicts, which come from where the functions sit.
   - The misses move between functions with the instruction counts unchanged (xc_lit +2.6 k, xc_held_run +2.2 k, vc_p07_c1
     +1.7 k against xc_hold_test -2.1 k, gu_drawn -1.7 k, ud_new -1.1 k). That is the signature of placement.
   - The order search's own figures say the same [C, order36_a.out against gl35's order35.out]:
     - The deck route's trace t0 (opening, deck and rain windows): 2,247,770 -> 2,263,098 I-misses (+0.7 %). Its held-out
       window 27,801 (the steady deck, not in the search) went 161,240 -> 169,030 (+4.8 %).
     - The inside route's trace t1: 2,624,216 -> 2,531,855 (-3.5 %), its held-out window +12 %.
     - The search minimises the plain sum of both traces' misses, so it bought t1's gain with t0's loss. The steady deck is not
       in its objective at all.
     - The opening has only an ME-turn window (16,001) among 8 in t0.
3. The D-miss part is data placement, not the order [I].
   - Its sign flips with the turn: +4.2 / +4.5 k in the ME turns, -2.9 / -9.3 k in the main turns. The same-ELF spread is under
     1 k.
   - Basis: the instructions are equal. Every heap block sits 11 KB higher (the ELF's growth, look a), and .bss and the heap's
     buffers move against each other's cache sets. The order places only code.
   - Averaged over the two turns of each scene (ME and main turns alternate), the base change is +0.73 ms a step on the deck and
     +0.23 in the opening. The ME-turn-only figures (+1.61, +1.94) overstate it.
   - The model's ME-turn windows run the ME's loop as a thread of the main CPU, through the main CPU's caches. On the PSP the ME
     has its own data cache, so this D-miss part may not carry over [I].
