# gl36 plan: reuse a native ship group's whole work from the last picture (in turns) + the drawn-areas keep everywhere + a retrain, 2026-11-21 21:55 UTC

Lead plan for the MGS2 port thread. gl35's PSP run (psp_harness.md "Build gl35", read 21:40) was exact (62/62, 916/916, 52/52 pictures = gl34's). What it says [C, PSP]:
- rain wait, ME turns: 85-88 ms a step; the ME is the limit (ME turn ~87 ms a step: walks 62.2 = people chain 2 18.8 + ship chain 3 19.2 + sorted prims/meshes chain 6 18.0 + stage program 3.2; frame ends + lists 17.1; idle 4.3). Main: logic 43 ms a step, waits for fills 8.5, GE wait 8.5.
- the native ship group costs the ME 60.8 us (keep 0) / 58.4 (keep 15), ~305 groups a step (~30,500 a turn, ~18 vertices each). Stages, us a timed group, keep 0 (each holds one ~0.46 us clock read): walk 5.8, register 9.8, A+D 5.1, call rest 1.2, host call + GS state 6.0, transform 4.8, positions 4.3, cut 4.5, attributes 1.5, texture 8.4, strips 1.6, GE transform 4.6, depth 2.2, into frame 1.4, way back 2.8, drawn areas 3.4, walk end 1.0.
- gl35's keeps: drawn areas -1.6 us a group (pays), texture +0.8 (costs), A+D equal in steady turns but spikes in the first keep turn of a scene (cause UNKNOWN); net step time ~-0.3 ms [I]. Retrain -0.9..-1.4 ME / -1.5 main a step (model said -4.0 / -5.1: ~4x over again).
Conclusion: shaving stages of a 60 us group gives a few percent. The lever must remove most of the per-group work.

## What gl36 is
1. Tree /home/claude/t36 = t35 (the delivered gl35). Base settings in EVERY turn: MGS2_NAT_FAST=1, MGS2_NAT_KEEP=1 (the drawn-areas keep only; bits 2/4/8 off) with gl35's known oddity fixed (the keep bits reset at each turn, so a keep-off turn has no keeps). Timers (MGS2_NAT_SPLIT=1) stay on.
2. **The lever, in turns (its own key, e.g. MGS2_NAT_REUSE_CYCLE=1,1,0,0):** most ship groups are static (876,258 of 993,411 groups flagged static in gl35's run). For a native ship group whose inputs are the same as when it was last translated (its packet bytes or the static stream's identity, the matrices and every translator / GS-model / texture-cache state its translation reads), emit the GE words recorded last time (a copy, or a GE CALL into kept words) and REPLAY the state effects the full translation leaves (counters, stamps, LRU links, drawn areas, texture-cache touches), the way gl35's keep design did for three stages, but for the whole group. If the camera-dependent parts (the cut test, positions) stop a whole-group reuse, say what part can be reused and what that is worth, and design for that part.
3. **Gate preference:** (a) GE words identical to the full translation in every picture (a reuse that copies words recomputed-equal), checked mode on the twin and the emulator with 0 differing; (b) only if (a) is impossible for a part that is worth it: pictures pixel-identical on the emulator in all 52 shots, the dense e3 pictures and the live captures, and the reason the words differ written down. State hashes must stay hashref c9ddb593 in every arm and order.
4. Target [C model + emulator timers]: the native ship ME time a group in the rain wait -50% or more against gl35's keep-0 arm (60.8 -> ~30 us), no loss elsewhere. Report the expected step-time gain honestly: with the ME saved, the main CPU (logic 43 + waits) becomes the next limit [I].
5. Retrain PGO + code order on t36 with both arms (new hot code; gl32 showed unprofiled new code costs 7-13 ms), as gl35 did; score against gl35.
6. cfg otherwise = gl35's delivered cfg (in place everywhere, FLIPWAIT_FROM=0, DZ X whole run, live captures, short run to 31,400).
