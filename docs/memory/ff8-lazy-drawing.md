Part of [[ff8-port]] / [[ff8-stage5]] / [[ff8-direct-translation]]. Alternative to the Media Engine for the exact drawing's pixel work (the ME card of 2026-11-11 22:52 was withdrawn by me 2026-11-12 05:40: with lazy drawing the exact drawing left in the field windows is under 0.1 ms a frame). Notes: /mnt/project-files/ff8/stage5_notes.md §1.12, §1.14.

- IDEA: a GPU command's timing is worked out at arrival (it feeds the game clock); its PIXEL work goes to an owed queue of its region (= a drawing area). Owed commands run in order before anything outside the scheme reads or writes those pixels, and are DROPPED when a later round into the region has overwritten (cover map, 1 bit a pixel, set by unconditional writes: fills, opaque rectangles, the non-zero texels of small textured rectangles) every pixel they could write. Kept out of the queue: commands whose texture or palette lies in a region, lines, everything in the interlace line-skip state. Small VRAM writes into textures that owed commands use keep the old pixels as PATCHES (FF8's 5x4 eye-blink copies); large ones run everything.
- The state hashes do NOT include VRAM: the check is a whole-VRAM sum (gpu_vram_sum; x86 env GPULAZYSUM=N, PSP cfg "vsum 1" with [vsum] lines) against the eager run.
- Facts: the field draws every second vblank into two buffers (0,0)-(319,223) and (512,0)-(831,223); a quiet frame is ~410 opaque 16x16 tiles + ~570 triangles; the read-backs that forced exact drawing read pixels outside these buffers.
- v1 (ref/gpu.c.lz1, PSP dev build a5): exact everywhere, 98.9% of exact pixels dropped on x86, but NO GAIN in the model (quiet 39.6 vs a4 38.4): 64-byte queue entries and per-command checks cost ~480 k instructions a frame, as much as the drawing skipped.
- v2 (ref/gpu.c since 2026-11-12 01:31): per-region ring of 32-bit words (STATE 4, RECT 5, TRI 8, FILL 3 words), state serials bumped in set_drawmode / E2-E6 / GP1, lz_fast flag, page and palette checks cached, whole-page source marks, compact mask table, dropped records marked dead in place. PEEK (gpu_lazy_peek / gpu_lazy_unpeek, up to 16 boxes, 81,920 px): owed commands replayed clipped to the boxes, the reader copies, the pixels are put back, nothing stops being owed; psp/ge_ff8.c stale_resolve1 peeks for its stale tiles (16 boxes / 40,960 px, else gpu_lazy_need). The replay sets g_emuprof 2 -> 1 so the profile counts it (work inside show_frame is otherwise not profiled).
- v2 CHECKS x86 (recomp/run_lz2 go.sh, go2.sh, cmp.py; GPULAZY 1 lazy, 2 lazy + picture model with peeks, 3 texcheck psxrcc_tc, 4 eager with the model's boxes): every whole-VRAM sum of 6 variants = the eager run's 40,000, 5,911 peek-box sums lazy = eager, ~250 M texel reads 0 outside their box; 98.8% of the played part's exact pixels dropped.
- GE renderer side (psp/ge_ff8.c, found through lazy drawing): unaligned 8x8 texture windows now drawn through private aligned copies (win_get); the stale test is row-exact (the menu's 216-row pictures left 8 stale rows that made every primitive fall back). Whole run: 4 primitives over stale tiles (before 149,540), 0 window refusals.
- PPSSPP dev builds, all exact (hashes, per-frame lines, whole-VRAM sums = the lazy-off run): a6 37.81 / 55.14, a7 36.45 / 46.38, a8 36.73 / 47.35 (model quiet / heavy; a4 = PSP s3 is 38.41 / 55.15). Then the profile-guided build pu1: [[ff8-pgo]].
- Not in any PSP build yet (s3 is out); in the s4 candidate: [[ff8-s4]].
