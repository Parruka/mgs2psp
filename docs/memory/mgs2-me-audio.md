- SWITCH-OFFS (real power-off, exact to the stop, no crash record): v26me2 38.6 min (OSTENT [I]), v26me3 r2 39.5 (USB), v24 r1 ~22 (ME OFF, USB), v30 r1 20.9 / r2 20.1 (cheap, ME on), v30me5 r1 1.5 (cheap, resting), gl1 r1 15.8 (vb ~15,765), gl2 r1 30.8 (vb ~26,100) (ME off, picture, cheap, no USB). gl2m (memory fix) r1 TO THE END 55.6 min, the first 44.6 on the cheap battery alone. - GL2D (2026-10-27 15:21): NOT a power-off: a crash the catcher caught at vb 26,108 (gl2's stop point): malloc(32 KB) = 0 in sif_push, a 1,110 KB codec load held whole as heap copies [C]; fixed in gl2m (memory MEMORY.md 'GL2D CRASH'). So gl2's stop was most likely the same shortage [I]; gl1's stop (after vb 15,759) and the ME-era stops are still unexplained.
- BATTERY: tests on a CHEAP battery charged by PC USB; OSTENT 1800 mAh on hand. A USB charge reads external 0 / charging 0 in battery.txt: only the gauge rises (gl2m, Ffm 17:43). Drain tells them apart (OSTENT -14%/-60 mV at 38 min, cheap -22..-25%/-108 mV).
- v30me5 "ME rests" (Ffm "Build it" 20:43): the ME HALTs when idle; the main CPU writes 0xBC100044=1 (kernel) to wake it; the ME writes 0xBC300008/0xBC300000. Only these 3 writes OKed (answering system RPCs needs a new OK). Stall check = mix stops + ME reset, game exact. Run 1 off at 1.5 min; run 2 (cheap, no USB) to the end, exact, +0.16 ms/step.
- STUDY (Ffm "Study first" 22:47; me_startup_study.md, uOFW-checked): our stub used 0xBFC00000 (the kernel's shared start code); Sony uses 0xBFC00040. v30me6b = stub at 0x40 only if the 7 kernel words match uOFW's + Sony's ME boot steps (0xBC100050=7, VME 0xBCC00010/70/30/40: OKed on Ffm's card "All of Sony's" 00:33). b run 1 clean; b runs 2+3 caught breaks in k_kick (EPC 0x08b4ed1c). CAUSE [C]: kernel-mode code at a user address + an interrupt = interruptman `break 0x3FF` (ARK-4 patches only 0x3FE), ~1 per 100k wakes. FIX v30me6c (-DME_KADDR: kcall passes fn|0x80000000), delivered 02:57 (Desktop\mg2 port\MGS2T_v30me6c). RULE: kernel-mode helpers always at their kernel alias. A wake costs 136 us (kuKernelCall flushes caches twice): task #57.
